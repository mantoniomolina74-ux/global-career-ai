# ADR-013.2 — Knowledge Domain Hierarchy

## Estado

Propuesto

## Fecha

2026-07-22

---

# 1. Contexto y Problema

El Knowledge Domain Intelligence Engine introdujo la capacidad de representar conocimiento profesional mediante dominios y competencias.

Las evoluciones anteriores establecieron:

* ADR-013: Knowledge Domain Intelligence Engine.
* ADR-013.1: Knowledge Domain Scoring Strategy.

Actualmente, los dominios funcionan como estructuras independientes con competencias asociadas.

Ejemplo:

```text
Procurement
 |
 +-- Supplier Management
 +-- Purchasing
```

Este modelo permite evaluar conocimiento dentro de un dominio, pero no representa relaciones entre dominios profesionales.

En el mundo laboral real, los conocimientos están organizados jerárquicamente.

Ejemplo:

```text
Supply Chain
      |
      +-- Procurement
      |
      +-- Logistics
      |
      +-- Inventory Management
```

El sistema necesita comprender que un dominio puede formar parte de otro dominio más amplio.

---

# 2. Decisión Arquitectónica

Se introduce el concepto de jerarquía de Knowledge Domains.

Un dominio podrá tener una relación opcional con un dominio superior:

```text
Parent Domain
      |
      |
Child Domain
```

Esta relación permitirá representar estructuras profesionales jerárquicas.

Ejemplo:

```text
Supply Chain
      |
      +-- Procurement
             |
             +-- Supplier Management
             +-- Purchasing
```

---

# 3. Nuevo Modelo Conceptual

La arquitectura evolucionará desde:

```text
Competency
     |
     ↓
Knowledge Domain
```

hacia:

```text
Knowledge Domain Hierarchy

Domain
 |
 +-- Child Domain
        |
        +-- Competencies
```

Los dominios podrán existir como:

* dominios raíz,
* subdominios,
* dominios especializados.

---

# 4. Nuevo Contrato Esperado

El modelo actual:

```ts
interface KnowledgeDomain {
  id: string;
  name: string;
  competencies: KnowledgeDomainCompetencyWeight[];
}
```

evolucionará hacia:

```ts
interface KnowledgeDomain {
  id: string;
  name: string;

  parentDomainId?: string;

  competencies:
    KnowledgeDomainCompetencyWeight[];
}
```

La relación será opcional para mantener compatibilidad con dominios existentes.

---

# 5. Estrategia de Jerarquía

La jerarquía deberá soportar:

## Dominios raíz

Ejemplo:

```text
Supply Chain
```

## Subdominios

Ejemplo:

```text
Supply Chain
      |
      +-- Procurement
```

## Especializaciones

Ejemplo:

```text
Procurement
      |
      +-- Supplier Management
```

---

# 6. Impacto en Scoring

ADR-013.1 define el scoring dentro de un dominio.

ADR-013.2 extenderá el modelo para permitir agregación jerárquica.

Ejemplo:

```text
Supply Chain Score

=
Weighted Child Domain Scores
+
Direct Competency Scores
```

Esto permitirá que un dominio superior represente el conocimiento acumulado de sus subdominios.

---

# 7. Validaciones Necesarias

La implementación deberá garantizar:

## Prevención de ciclos

No permitir:

```text
A
 |
 B
 |
 A
```

## Control de profundidad

La jerarquía debe mantener una profundidad razonable.

Recomendación inicial:

```text
3-4 niveles máximos
```

## Integridad referencial

Un dominio hijo debe apuntar a un dominio existente.

---

# 8. Beneficios Arquitectónicos

Esta evolución permitirá:

## Matching profesional avanzado

Relacionar candidatos y posiciones mediante proximidad de conocimiento.

Ejemplo:

```text
Procurement Specialist
        |
        ↓
Supply Chain Analyst
```

## Career Transfer Intelligence

Identificar caminos profesionales relacionados.

## Learning Intelligence

Crear rutas de aprendizaje basadas en dominios.

---

# 9. Impacto Futuro

Knowledge Domain Hierarchy será la base para:

* mapas profesionales,
* recomendaciones de carrera,
* navegación semántica,
* knowledge graph profesional,
* inteligencia de transferencia laboral.

---

# 10. Resultado Esperado

ADR-013.2 establece la evolución del Knowledge Domain Engine desde un modelo plano hacia una estructura jerárquica de conocimiento profesional.

Esta decisión prepara Global Career AI para representar relaciones complejas entre competencias, dominios y trayectorias profesionales.
